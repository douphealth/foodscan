# FoodScan 9.2 upgrade plan (audit of 9.1.0)

Goal: fewer taps to a trustworthy verdict, a reason to return daily, and honest revenue growth.
Nothing here changes production; 9.1.0 stays the rollback.

## Audit findings (from source)

1. Worker budget is tight for growth. `_worker.js` allows 12 upstream reads/min per instance and 10/min per IP. A traffic spike returns `local_rate_limited`. Open Food Facts documents higher read allowances, so raise budgets only after confirming current OFF limits, and move counters to a shared store (KV or a rate-limit binding) because per-isolate counters are best effort.
2. Cold start shows a loading message and preloads about 25 modules. Add a static, scan-first HTML shell (big Scan button, name search) rendered before JS, so first paint is already useful.
3. Verdict language is accurate but blunt in places ("Leave it."). Keep the safety rules in `decision.js`, and add a one-glance verdict card: colour + icon + one sentence + top 3 reasons + better swap, with details collapsed.
4. No measurement. Today the only analytics are local counters. Add consent-aware GA4 (or privacy-first alternative) events: scan_success, scan_miss, verdict_view, swap_click, list_add, pantry_add, merchant_click, install. Needs a measurement ID and a consent banner decision.
5. Misses are dead ends. On `not_found`, offer: retry with typed barcode, name search, label-photo flow (`photos.js`), and a link to add the product to Open Food Facts.
6. Single market affiliate: merchant links exist only on pending groceries (`commerce.js`). Extend to swap suggestions and restock, keep the paid-link label and disclosure, and only add market tags that exist in Associates Central.
7. English only. Add UI strings and `hreflang` pages starting with Greek.

## Release rules

- Bump version, asset folder and service-worker cache together (9.2.0), and update the precache list.
- Test on staging with a real camera, a real barcode, offline revisit, and a hard restriction profile.
- Claim no retention or revenue lift until measured against the 14-day scorecard in RELEASE_NOTES.md.
